# JEV x Tetris

用**一次前向**让本地模型下俄罗斯方块：每一步都给候选落点（r 旋转 / c 列 / L 消行 / H 洞 /
T 高度 / B 凹凸 / S 引擎分），模型要报出 **S 最大的那个字母**。

每次决策就是一次 JEV 调用 —— `max_tokens = 1 + logprobs + top_logprobs = 40`，
读候选字母位的 logits 后重归一化成概率，**不额外解码任何 token**。页面上能直接看到
每一步的概率分布、`prompt_n` / 缓存命中 / 耗时。

## 跑起来

模型服务**不在本目录启动**，先在别处起 `..\llmserver.bat`（固定 **18080**），然后：

```
run.bat
```

`run.bat` 只做三件事：找 python → 检查 18080 是否在答（不在答就只警告，**不替你启服务**）
→ 起 `bridge.py`（UI 服务，**18090**）并打开浏览器。**关掉那个窗口 = 停 UI。**

```
UI      http://127.0.0.1:18090/
model   http://127.0.0.1:18080/
```

## 界面

**通栏页头 + 左游戏 / 右面板**，整屏铺满、**不滚动**（`height:100dvh`）。

- **页头（通栏）**：logo · `JEV × Tetris` · 右侧模型在线状态（带模型名）。横跨整页宽度，
  不归任何一栏 —— 标题只是标题，不是某个面板里的元素。
- **左 · 游戏**：**黑底**标准俄罗斯方块 —— 网格线、按方块类型着色的堆叠块、上高光下阴影的
  立体块、落点虚线框、下一个方块。右侧一条 HUD：下一个 / 消行 / 决策次数 / 落子每秒，
  与棋盘**同高**（竖向摊开铺满，不留空黑）。
  棋盘**只按可用高度**定尺寸（`fit()` 算格子边长，再按 `devicePixelRatio` 放大画布），
  宽度随之自然落地；**左列列宽由内容决定**（`grid-template-columns:auto …`），
  所以无论窗口多宽多矮，棋盘都刚好铺满左列 —— 不会两侧/上下留大片空黑。
  注意：`fit()` **刻意不读棋盘自身容器的宽度**，否则「画布撑宽列宽、列宽又反过来算画布」
  会死循环（历史故障：格子卡在 30）。
- **右 · 上菜单**：`▶ 开始 / ⏸ 暂停` · `⏭ 单步` · `↺ 重置` · 决策方式
  （`JEV 判据 / 生成式 / 思考`）· 间隔 · 模式说明。
- **右 · 下状态区**：本次决策耗时（大字）+ `prompt tok / 缓存复用`，然后是**候选概率列表**，
  最后是耗时曲线与折叠的「模型实际看到的 prompt」。内容长了只在这个区域内滚。

候选列表按概率降序排，**序号就是名次，第一行就是模型的选择**：

```
1   r1 c5  引擎最优  ████████████████████████  99.4%
2   r0 c4           ▏                          0.4%
3   r0 c6           ▏                          0.1%
```

行里**不出现 A/B/C/D**（那是判据协议给模型的字母，在 prompt 面板里能看到）；只有
「引擎最优」那一行带一个小标记 —— 它落在第一行，就说明模型和引擎选到一块了。

### URL 开关（给人少用，脚本/截图用）

| 参数 | 作用 |
|---|---|
| `?auto=1` | 打开就自动开始跑 |
| `?gap=0\|400\|1200` | 决策间隔（ms） |
| `?mode=jev\|gen\|think` | 决策方式 |
| `?repr=compact\|grid` | 状态表示：紧凑（列高+洞数）/ 网格（20×10 字符）。**只留 URL 开关**，页面上没有这个控件了 |

## 三种决策模式（页面顶栏可切）

| 模式 | 调用形态 | 说明 |
|---|---|---|
| `jev` | `max_tokens=1` + `logprobs` + `top_logprobs=40`，`enable_thinking=false` | 默认。一次前向、零解码，拿到全部候选概率 |
| `gen` | `max_tokens=12`，温度 0 | 只让模型报一个字母，对比「不给概率」差在哪 |
| `think` | `max_tokens=512`，温度 0.6，开思考 | 让它慢慢想，慢很多，作为上限参照 |

实测同一盘面（8 个候选、S 从 10 递减）：`jev` 969 ms / `p=0.9998` 选 A（正确）、
`gen` 197 ms（命中缓存）/ 报 A、`think` 2746 ms / 报 A。

## 目录

| 路径 | 作用 |
|---|---|
| `run.bat` | 启动器（找 python → 探 18080 → 起 bridge → 开浏览器） |
| `bridge.py` | 同源后端：拼 prompt、转发 18080、把概率算好回给页面（stdlib only） |
| `index.html` | 游戏 + 判据面板（棋盘、重力、计分、概率列表、耗时曲线） |
| `shots\` | 演示截图（`ui_empty.png` 开局 / `ui.png` 跑了一段 / `ui_wait.png` 间隔相位） |
| `tools\` | 开发期脚本（见下） |
| `tools\logs\` | 这些脚本的服务日志 |

### tools\ 里的东西

| 文件 | 作用 |
|---|---|
| `play.js` | 无头跑 N 步，直接打 bridge 的 `/api/decide`（`node tools/play.js 50`） |
| `playtest.py` | 一条命令闭环：探端口 → 起 llmserver + bridge → 跑 play.js → 按 PID 杀 |
| `sim.js` | 游戏规则仿真（落点枚举 / 打分），与 index.html 同一套算法 |
| `smoke.py` | 只测模型端点（`/v1/chat/completions` 的 JEV 形态），不碰 UI |
| `visual.py` | 截图走查（页面渲染是否正常） |
| `http_probe.py` | 端口/健康探针，启动顺序排查用 |

⚠️ `tools\` 里的脚本会**自己起 18080 的 llmserver**（探到端口被占就 abort）—— 这是开发期
工具的用法；日常只用 `run.bat`，服务由你自己起。
