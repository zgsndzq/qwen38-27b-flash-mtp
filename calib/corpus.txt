A hash map is a data structure that implements an **abstract hash table**. It allows for very fast retrieval of elements based on their keys. Below is a detailed explanation of its internal mechanics and how it handles collisions.

---

### 1. Core Components

A hash map typically consists of:
- **Keys**: The input data used to look up values.
- **Values**: The associated data.
- **Buckets (or Array Slots)**: An internal array where key-value pairs are stored.
- **Hash Function**: A mathematical function that takes a key and produces an integer index (the "hash code") into the bucket array.

---

### 2. How It Works Step-by-Step

#### A. Hashing a Key
When you call `put(key, value)`:
1. The **hash function** computes an integer hash code from the key.
   - Example: `hash("apple")` might produce `14372034`.
   - For strings, this is often the sum of character codes multiplied by powers of a constant (e.g., Java’s `String.hashCode()`).
2. The hash code is mapped to a valid bucket index:
   - `index = hash_code % capacity`
   - Where `capacity` is the size of the internal array.
   - Example: If `capacity = 10`, then `14372034 % 10 = 4`. So, the value is stored in bucket 4.

#### B. Retrieving a Value
When you call `get(key)`:
1. Compute the same hash code.
2. Calculate the bucket index: `index = hash_code % capacity`.
3. Go to that bucket and search for the key.

---

### 3. Collision Handling

A **collision** occurs when two different keys hash to the same bucket index.

Recursion is a technique in computer science where a function solves a problem by **calling itself** to solve smaller, simpler versions of the same problem. It requires three key components:

1. **Base Case**: The simplest version of the problem that can be solved directly without further recursion.
2. **Recursive Case**: The part of the function that breaks the problem into smaller subproblems and calls itself.
3. **Progress**: The recursive calls must move toward the base case (otherwise, the function will run indefinitely).

---

### Example 1: Numeric – Factorial Calculation

The factorial of a non-negative integer \( n \), denoted \( n! \), is the product of all positive integers less than or equal to \( n \).

**Definition**:
- \( 0! = 1 \)
- \( n! = n \times (n-1)! \)

This is naturally recursive.

**Python Code**:
```python
def factorial(n):
    # Base case
    if n == 0:
        return 1
    # Recursive case
    else:
        return n * factorial(n - 1)
```

**How it works for `factorial(4)`**:
```
factorial(4)
= 4 * factorial(3)
= 4 * (3 * factorial(2))
= 4 * (3 * (2 * factorial(1)))
= 4 * (3 * (2 * (1 * factorial(0))))
= 4 * (3 * (2 * (1 * 1)))        # Base case hit
= 4 * (3 * (2 * 1))
= 4 * (3 * 2)
= 4 * 6
= 24
```

**Key Points**:
- The **base case** is `n == 0`.

三值量化（Ternary Quantization）是一种高效的模型压缩技术，其核心思想是将模型中原本精度较高的权重参数（通常使用 32 位浮点数 FP32 或 16 位半精度 FP16）映射为仅由三个离散数值组成的集合。

在传统的二值量化中，数值通常被压缩为 $\{0, 1\}$ 或 $\{-1, 1\}$，而三值量化则进一步扩展至 $\{-1, 0, 1\}$。这种映射过程将大量连续变化的数值“归一化”到这三个固定的刻度上。例如，所有接近 0.5 的权重可能都直接归并为 0.5，所有接近 -0.5 的归为 -0.5，或者更常见的做法是将范围划分为三段，直接映射为 $\{-1, 0, 1\}$。

三值量化之所以能大幅节省显存，根本原因在于**信息位宽的大幅降低**。在 FP32 下，每个参数占用 4 字节；即使采用 FP16，也需 2 字节。而在三值量化后，每个参数仅需存储 2 个比特（bit）即可表示 -1、0 或 1 三种状态。理论上，这能将模型显存占用从 4 字节/参数降至约 0.25 字节/参数（即 16 倍的压缩比）。即使考虑到需要额外存储缩放因子（scale）和偏移量（offset）以恢复精度，三值量化带来的显存缩减幅度也远超其他量化方法，从而使得大语言模型可以在消费级 GPU 上高效运行。

与传统的数据库（如银行系统）不同，区块链的核心特点如下：

1. **分布式网络**：数据不是存储在单一服务器上，而是复制并同步到全球成千上万个节点（电脑）上。
2. **不可篡改（Immutable）**：一旦数据被记录在区块链上，就很难被修改或删除。因为每个“区块”都包含前一个区块的哈希值（数字指纹），如果修改历史数据，所有后续区块的验证都会失败，整个网络会拒绝该数据。
3. **透明与公开**：大多数区块链（如比特币）是公开的，任何人都可以查看链上的交易记录（但通常无法看到交易者的真实身份，除非使用隐私保护技术）。
4. **去中心化**：没有单一的中央机构（如银行或政府）控制整个网络，而是通过共识机制（如工作量证明、权益证明）来验证和确认交易。

### 实际应用场景例子：**供应链追踪（以钻石或食品为例）**

#### 场景：**钻石供应链追踪**

传统钻石贸易存在“血钻”（通过战争或非法手段开采的钻石）问题，消费者很难确认自己购买的钻石是否是道德、合法的。区块链可以解决这个问题。

#### 如何工作？

1. **开采阶段**：矿工开采出原石钻石后，将其基本信息（重量、颜色、来源矿山、时间）记录到区块链上，并生成唯一的数字标识（如NFT或哈希值）。
2. **切割与加工**：钻石被切割、抛光后，加工商将更新后的信息（切割规格、证书）添加到链上，关联原始钻石的唯一标识。
3. **零售阶段**：零售商收到钻石后，再次确认交易并记录到链上。
