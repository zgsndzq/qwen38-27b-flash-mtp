# 开源发布演练报告

**日期** 2026-10-15　**目的** 用一个独立目录模拟真实使用者，验证"只下载、不编译"和"下载源码、自己编译"
两条路都能跑起来，并把发布物缺的东西暴露出来。

---

## 一、演练怎么搭的

模拟**三个发布渠道** + **一台干净的用户机**：

| 模拟物 | 对应真实渠道 | 内容 | 体积 |
|---|---|---|---|
| `_release_out\hf-model\Ternary-Bonsai-2-27B-PTQ1_0-GGUF\` | Hugging Face model repo | 6 个 gguf + `README.md`(model card) + `SHA256SUMS` | 29.4 GB |
| `_release_out\github-src.git\` | GitHub 源码仓 | `git clone --bare` 出来的裸仓 | 349 MB |
| `_release_out\releases\` | GitHub Releases | `ada-ternary-win64-sm89-b3e7c012.zip`(568 MB)、`ada-ternary-src-b3e7c012.zip`(37 MB) | 605 MB |
| **`duan\`** | **用户机** | 只从上面三处"下载"，**零指向 `qwen27b`** | — |

用户机的最终形态（就是 `F:\super\duan`）：

```
duan\
├── README-FIRST.md            ← 使用者拿到手先看的说明
├── ada-ternary\               ← Release zip 解包
│   ├── build\bin\  build\cuda\        预编译二进制 + CUDA 运行时
│   ├── weights\                       从 HF 下的 gguf（硬链接，省 29 GB）
│   ├── maps\  llmchat\               草稿短名单 + 客户端
│   └── llmserver.bat  features.ini
├── code\                      ← GitHub clone 的源码（场景 B 用）
└── build\src\  build\logs\    ← 用户自己编译的产物（场景 B）
```

> 权重用**硬链接**而非真拷贝：路径与目录项完全独立，但省掉 29 GB 和十几分钟复制时间。
> 真实使用者走 HF 下载，这是唯一的简化点。

## 二、结果：两条路都通

### 场景 A —— 只下载，不编译 ✅

```
1) 解压 ada-ternary-win64-sm89-b3e7c012.zip                    (49 s)
2) 从 HF 目录取 6 个 gguf 到 ada-ternary\weights\
3) 双击 ada-ternary\llmserver.bat

    load_model: loading model 'F:\super\duan\ada-ternary\weights\Swift-Bonsai-2-PTQ1_0-mtp-pro-q4km.gguf'
    adaq8: feature file features.ini -> 11 applied, 0 ignored
    MTP draft context uses the draft-only vocabulary shortlist 'maps/shortlist_24k_mix.vocab.txt'
    load_model: loaded multimodal model, '...\weights\mmproj-Qwen3.8-27B-Q8_0.gguf'
    llama_server: listening on http://127.0.0.1:18080

    3 次请求全部正常出码：60.1 / 72.1 / 80.6 t/s
    包内客户端 llmchat\chat.py 也正常连上（服务端模型 Ternary-Bonsai-2-27B）
```

**关键点**：整条链路零绝对路径 —— `llmserver.bat` 全靠 `%~dp0`，`--features-file features.ini` 靠首行
`cd /d %~dp0` 定位。zip 里带了 CUDA 运行时，所以用户**不需要装 CUDA Toolkit**。

### 场景 B —— 下载源码，自己编译 ✅

```
1) git clone github-src.git  ->  duan\code
2) copy build.local.example.bat build.local.bat   然后填 6 个值
3) _build_q8.bat

    560/560 目标   CFG_EXIT=0  BUILD_EXIT=0  SERVER_OK  DONE     (约 20 分钟)
    源码路径确认是 F:/super/duan/code/...（用的是用户自己的树）

4) 产物覆盖到 ada-ternary\build\bin\ 再启动 -> 正常
    71.4 / 67.5 / 80.6 t/s
```

**缺 `build.local.bat` 不会静默出错** —— 脚本写 `MISSING build.local.bat` 并退出（码 9），
不会在别处乱建目录。这条设计是对的。

**自编译产物 vs Release 二进制：sha256 全部不同**（编译路径与时间戳嵌进了二进制），
但行为一致 —— 这是正常的，不是问题。

## 三、发现的问题

### 🔴 A 类：上传前必须改（这些会直接暴露给使用者）

| # | 位置 | 问题 |
|---|---|---|
| A1 | `llmchat\README.md` | 有**绝对路径** `F:\super\qwen27b\models\Ternary-...gguf`，而且 `models` 早就改名 `weights` 了 |
| A2 | `llmchat\README.md`、`llmchat\llmchat.bat` | 多处 `..\qwen27b\llmserver.bat` —— 内部目录名，解包后叫 `ada-ternary`，指向是错的 |
| A3 | `llmchat\imgtest.py:135` | **print 出来的用户可见提示**写着 `请先启动 qwen27b\llmserver.bat` |
| A4 | `README.md` / `README.en.md` | 有整节 **"与 `..\adaq8\` 的关系（正在合并）"** —— 内部搬家记录，含 `junction` 之类的私事 |
| A5 | 两份 README 标题 | 叫 `# qwen27b — ...`，是内部代号 |
| A6 | `features.ini:2` | `;  qwen27b - fork feature file` |
| A7 | 引擎 `common\arg.cpp`、`common.h` | `adaq8:` 前缀出现在 **`--help` 文案**和**运行日志**里（启动日志满屏 `adaq8: feature set ...`） |
| A8 | 发布包 `llmchat\mem\` | **带上了作者的私人记忆库**（`chess.png` / `chess1.png`）；客户端默认 `MEM=2` 会把它注入每一次首轮对话。演练时新"用户"一问就被塞了两张象棋图 |
| A9 | `llmchat\llmchat.bat` | 默认 `VISION=1` + 记忆模式 2 —— 新用户一上来走的就是作者的工作流 |

**包名也是 A 类问题**：对外叫什么还没定，`qwen27b` 不能出。建议 `ada-ternary`（与 Release 文件名一致）。

### 🟡 B 类：建议在发布前处理

| # | 问题 | 处理 |
|---|---|---|
| B1 | **源码仓是 shallow 的** —— 11016 个提交，边界 `f4f7758ca`。clone 下来看不到更早的历史 | 发布前 `git fetch --unshallow`（要网络+代理，几百 MB） |
| B2 | Release 包与构建脚本**目标集合不一致** —— 包里有 `llama-quantize.exe` / `llama-spec-tree.exe`，而 `_build_q8.bat` 只编 `llama-server / llama-bench / test-backend-ops` | 二选一：脚本补上这两个目标，或从包里去掉 |
| B3 | **model card 的 base model 与许可证填不了** —— gguf 元数据里**没有** `license` / `author` / `base_model` 字段（只有 `general.name = Swift-Bonsai-2-merged-PTQ1_0`、架构 `qwen35`） | 必须人工确认上游仓库与其许可证；这是**衍生模型**，许可跟随 base，不能声明为原创 |
| B4 | 仓库里没有 `LICENSE` 文件、没有 `SHA256SUMS` 之外的发布清单 | 补 LICENSE（MIT，同上游）+ 一份 `RELEASE.md` |
| B5 | 二进制里嵌着本机路径字符串（`F:\super\qwen27b\...`，575 个文件命中） | 无害（调试段），重编即变。可不管 |

### ⚪ C 类：记录，不算问题

- 自编译与 Release 的 sha256 差异 —— 编译路径/时间戳所致。
- `build\bin\*.dll` 里的路径字符串 —— 调试信息。
- 权重 29.4 GB 走 HF 单文件上传即可，不用切分。

## 五、结论

**技术上已经具备发布条件** —— 两条使用者路径都在独立目录里跑通了，运行侧零外部依赖，
构建侧靠一份 `build.local.bat` 就能适配别的机器。

**卡住的不是技术，是"内部痕迹"**：A 类 9 条全是把内部命名、内部搬家记录、作者私人数据
带了出去。这些不修，使用者第一眼就会看到 `qwen27b`、`adaq8`、"与 adaq8 的关系"、
以及两张莫名其妙的象棋图。

**下一个动作**：按 A 类清单改一遍，然后重打包、让 `duan` 重新下载验证一次。
